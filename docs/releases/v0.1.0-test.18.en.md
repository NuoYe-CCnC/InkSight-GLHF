## Changes

- Bounded author-reply and numbered-series context recognizes explicit Codex/reset plans, corrections, delays and cancellations. It cannot borrow another event's time or turn an unspecified plan into universal eligibility. Deterministic rules do not call a paid model to guess.
- Midnight and relative dates use the original post time, distinguishing PST/PDT/PT. Beijing-time presentation supports exact time, date range and unknown time. Expiry is separate from the predicted event time.
- Active announcements add an optional Is star and a revalidated original-source action. Identity, revision, expiry and URL are checked again at activation; a stale click cannot silently open a different event.
- Auxiliary sources independently recover from temporary failures with bounded +10/+30-minute retries, persisted budgets, nighttime limits and 429/access rules. Auxiliary retries do not cause extra primary-source probes; no X Cookie/token or TLS bypass is used.
- Local diagnostics distinguish transport/parsing failures and separate first-seen/recognized, snapshot, publication readback and device evidence. Reading diagnostics does not trigger an upstream request.
- README now prioritizes App download, three-step setup and hardware references. Demo images use the actual renderer, isolated native forecast-menu component and management UI, with synthetic values and an explicitly historical clock. No USB write was performed for the setup image.

Actual quota, manual reset counts/expiry, ledgers, news and page switching are independent of announcements. Active forecasts temporarily occupy the approved optional API/credits area, restoring those options on expiry. **Experimental announcements default to false**, while upgrades preserve existing switches. Sources may be incomplete; advance notice, personal eligibility and personal delivery are not guaranteed.

## Upgrade

App-only improvements do not require reflashing just to match version numbers. **Full v2 announcement support needs the updated App and firmware supporting `announcement_schema_max >= 2`**. Old v1-only firmware is not v2 capable. No active announcement means no star or prediction text.

Exit normally and back up current private data before replacing the complete App at the same path. Check the single publisher. If device-side v2 is wanted, use the [preparation center](../DEVICE_FIRST_USE.zh-CN.md) and [existing-device update](../UPGRADE.zh-CN.md): identify the board/partition layout, verify backups, write only the inactive slot, read back fully and verify protected regions before changing the startup selector. Preserve NVS/Wi-Fi/filesystem; do not erase the board or overwrite current networks with compiled defaults. A rollback must preserve records created after upgrading.
