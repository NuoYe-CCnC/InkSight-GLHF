# 升级已有主机与设备

[文档目录](README.md) · [当前测试版说明](releases/v0.1.0-test.17.zh-CN.md) · [Mac App 使用](APP_DESKTOP.zh-CN.md) · [完整安装与受控刷写](INSTALLATION.zh-CN.md) · [实验性固件回退流程](FIRMWARE_UPDATE_ROLLBACK.zh-CN.md)

先读**目标版本Release说明**。test.17汇总公开test.9之后的准备中心、发布快照、实验预告和恢复应用修复。已有固件若兼容，仅更新电脑App无需为版本号一致重复烧录；若要新增设备端功能，先核对固件能力、精确板型和配套源码。切换前正常退出旧发布者及其自动重启，备份最新配置、账本、预算、出刊与请求去重状态。独立数据目录的文件锁不能阻止两个实例同时写同一云端设备；迁移或回退不能倒灌旧快照覆盖新增记录。

## 已有 App 升级到 test.18

test.18 的主机功能和设备端 v2 预告需要分别核对；不要只看 App/固件版本号是否一致。

1. 确认没有在途构建、USB 写入或付费任务，从 Is →“退出 InkSight”正常退出，确认旧后端与发布者已停止。
2. 在私有位置备份旧 App、`~/Library/Application Support/InkSight-GLHF/` 及系统偏好。保存此刻最新的配置、账本、预算、Token、去重与出刊状态；不要用早先快照覆盖新记录。
3. 校验同版 App ZIP，在原安装路径替换完整 App。打开新版后检查受管迁移、唯一 Is/后端/发布者、配置与缓存；已有用户的实验开关保留，新安装预告默认关闭。不要重置配置或同时运行两个发布端。
4. 仅需用量、简报、金价等原有能力时，兼容的旧设备可继续使用，不为统一版本号重刷。**完整启用本版 v2 预告必须更新到支持 `announcement_schema_max >= 2` 的固件。** 旧版只读 v1 的固件不能正确显示待定时间、类型与原文对应契约；App 已更新不等于设备已具备 v2。
5. 需要 v2 时，在[设备准备中心](DEVICE_FIRST_USE.zh-CN.md)合法导入字体、准备工具、检查配置并构建自己的固件。接入支持的数据线后复核设备身份、容量、分区和当前活动槽，走**已有设备 update**流程；拒绝条件不得绕过，不选空白板 fresh，也不整片擦除。
6. 完整备份可读后，只写非活动应用槽，完整回读并核对原活动应用、NVS、文件系统与引导等受保护区域后再切换启动项。已有有效 Wi-Fi 顺序/密码和设置保留，不以编译默认值替换。
7. 分别确认匹配构建的联网回执、v2 能力和实体屏底栏更新时间；当前没有有效预告时不应出现“预计”或星号。人工检查白屏、乱码、重叠和反复重启；云端 GET 回读不能替代设备及实屏确认。

本版在一块现有设备完成上述保留数据升级，用户确认刷新正常；没有实测空白板、另一台 Mac、真实回退、重新登录自启或所有界面状态。回退前保存升级后新增数据并核对兼容性；保留的旧应用槽及备份不是已实测回退的承诺。

## 改用独立 Mac App

App 会在当前用户的 `Application Support/InkSight-GLHF/` 下建立自己的私有版本目录，**不会自动读取或修改现有源码部署**。先在私有位置完整备份旧源码目录的配置、数据库和状态。停旧后端与发布循环，再打开 App；需要迁移时使用 App 的“选择性导入旧源码数据”预览、备份、确认流程，随后逐项核对本机管理页、采集状态与云端发布。不要同时运行两个发布端来操作同一设备。若已有 App 旧版，新版会保留旧版本目录并复制受管私有数据；升级前仍须自行备份。回退时先停新 App，保留运行后最新数据，再按兼容范围受控恢复旧程序与状态；本版没有一键回退按钮。详见[Mac App 使用说明](APP_DESKTOP.zh-CN.md)。

## 开始前

1. 停止前台后端与发布器，记录当前使用的源码版本、设备固件目标与配置 schema。不要把升级和日常发布同时运行。
2. 在**本机私有位置**备份当前源码、`shared/config/` 内真实配置、`shared/backend/` 下的数据库与 `state/`、本机 `.env`，并核对备份能读；不要提交、上传 Issue 或分享。升级版本如另有迁移说明，以该版本为准。
3. 下载[目标版本的源码和同版校验文件](DOWNLOAD.zh-CN.md)，检查 SHA-256。不要把 GitHub 自动生成源码 ZIP 当作已验收的发行资产。

## 仅更新源码后端（test.2 用户可继续走这条）

把新源码放在**新的独立目录**，先按[首次使用](FIRST_USE.zh-CN.md)安装该版本的锁定依赖。不要对生产目录运行空白 `init` 或把新示例文件覆盖自己的私密配置；将备份的配置与状态按对应版本说明受控迁移，再执行 `shared/tools/inksight_config.py validate`。若仍使用旧 `manual_settings.json`，先执行 `migrate --dry-run`，审阅后才决定是否 `--apply --confirm-activate`。更换源码与状态的一致性由部署者核对，切勿把新状态随意交给旧版代码读取。

确认无误后用新版本 `shared/backend/run-backend.sh` 前台启动，检查本机 `http://127.0.0.1:8080/api/health`、管理端及实际需要的数据时间戳。单一健康返回不证明报价或设备发布新鲜；若使用坚果云，再按[主机发布指南](HOST_RUNTIME.zh-CN.md)做一次发布/回读核验。主机需保持唤醒，睡眠期间不保证出刊。

## 只有目标版本明确要求时才刷写固件

当前测试版没有可下载的固件 `.bin`。要自行构建，先按[完整安装指南](INSTALLATION.zh-CN.md)合法取得/导入 MiSans，显式指定 `epd_426_ssd1677_s3_n32r16`；不要直接用 `platformio.ini` 中的历史默认环境。管理端受控流程区分真正空白板的 `fresh` 与已有设备的 `update`：后者要求分区表匹配、先备份 NVS/OTA/应用区、写未运行分区并校验。不要对未知设备猜串口、全盘擦除或绕开拒绝条件。新板使用编译的Wi-Fi列表作为初始优先级；支持的兼容升级保留已有有效NVS列表，不会因主机编译配置变化隐式删除/替换现用网络。需要修改设备网络时另走经确认的配网流程。

## 回退

先停止新后端/发布器，私密保存运行后最新账本、预算、出刊及请求去重记录。旧版 [test.5](https://github.com/NuoYe-CCnC/InkSight-GLHF/releases/tag/v0.1.0-test.5)程序仍可下载，但不可直接倒灌升级前快照造成重复付费；先核对状态兼容性，必要时请维护者协助受控迁移，再启动唯一旧发布者。不能只降代码而让旧版解释新版状态。设备若实际刷写过，按对应受控备份和回退说明处理；本次未提供固件，不声称有已验收的设备端一键回退。回退失败请保留私有备份和日志，按[故障排查](TROUBLESHOOTING.zh-CN.md)定位，不要公开凭据。
