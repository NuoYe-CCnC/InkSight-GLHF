# 升级已有主机与设备

[文档目录](README.md) · [当前测试版说明](releases/v0.1.0-test.3.zh-CN.md) · [Mac App 使用](APP_DESKTOP.zh-CN.md) · [完整安装与受控刷写](INSTALLATION.zh-CN.md)

先读**目标版本 Release 说明**，确认它究竟是后端更新、固件更新还是两者都有。`v0.1.0-test.3` 新增独立 Mac App，不含新固件二进制，不要求为了本次主机更新刷屏。此前 test.2 附件保持不变。

## 改用独立 Mac App

App 会在当前用户的 `Application Support/InkSight-GLHF/` 下建立自己的私有版本目录，**不会自动读取或修改现有源码部署**。先在私有位置完整备份旧源码目录的配置、数据库和状态。停旧后端与发布循环，再打开 App；需要迁移时使用 App 的“选择性导入旧源码数据”预览、备份、确认流程，随后逐项核对本机管理页、采集状态与云端发布。不要同时运行两个发布端来操作同一设备。若已有 App 旧版，新版会保留旧版本目录并复制受管私有数据；升级前仍须自行备份。回退时停新 App，恢复同一时点的旧程序和旧状态；本版没有一键回退按钮。详见[Mac App 使用说明](APP_DESKTOP.zh-CN.md)。

## 开始前

1. 停止前台后端与发布器，记录当前使用的源码版本、设备固件目标与配置 schema。不要把升级和日常发布同时运行。
2. 在**本机私有位置**备份当前源码、`shared/config/` 内真实配置、`shared/backend/` 下的数据库与 `state/`、本机 `.env`，并核对备份能读；不要提交、上传 Issue 或分享。升级版本如另有迁移说明，以该版本为准。
3. 下载[目标版本的源码和同版校验文件](DOWNLOAD.zh-CN.md)，检查 SHA-256。不要把 GitHub 自动生成源码 ZIP 当作已验收的发行资产。

## 仅更新源码后端（test.2 用户可继续走这条）

把新源码放在**新的独立目录**，先按[首次使用](FIRST_USE.zh-CN.md)安装该版本的锁定依赖。不要对生产目录运行空白 `init` 或把新示例文件覆盖自己的私密配置；将备份的配置与状态按对应版本说明受控迁移，再执行 `shared/tools/inksight_config.py validate`。若仍使用旧 `manual_settings.json`，先执行 `migrate --dry-run`，审阅后才决定是否 `--apply --confirm-activate`。更换源码与状态的一致性由部署者核对，切勿把新状态随意交给旧版代码读取。

确认无误后用新版本 `shared/backend/run-backend.sh` 前台启动，检查本机 `http://127.0.0.1:8080/api/health`、管理端及实际需要的数据时间戳。单一健康返回不证明报价或设备发布新鲜；若使用坚果云，再按[主机发布指南](HOST_RUNTIME.zh-CN.md)做一次发布/回读核验。主机需保持唤醒，睡眠期间不保证出刊。

## 只有目标版本明确要求时才刷写固件

当前测试版没有可下载的固件 `.bin`。要自行构建，先按[完整安装指南](INSTALLATION.zh-CN.md)合法取得/导入 MiSans，显式指定 `epd_426_ssd1677_s3_n32r16`；不要直接用 `platformio.ini` 中的历史默认环境。管理端受控流程区分真正空白板的 `fresh` 与已有设备的 `update`：后者要求分区表匹配、先备份 NVS/OTA/应用区、写未运行分区并校验。不要对未知设备猜串口、全盘擦除或绕开拒绝条件。Wi-Fi 列表是下次构建的完整快照，省略的旧网络可能在新固件首次启动时从 NVS 删除。

## 回退

先停止新后端/发布器，再恢复**升级前同一时点**的源码、配置、数据库与状态，最后启动旧版并核对健康与数据；不能只降代码而让旧版解释新版状态。设备若实际刷写过，按该版本的受控备份和回退说明处理；本版 test.2 未提供固件，不能声称有设备端一键回退。回退失败请保留私有备份和日志，按[故障排查](TROUBLESHOOTING.zh-CN.md)定位，不要公开凭据。
