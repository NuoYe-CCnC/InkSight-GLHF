# Apple 订阅日期与 Codex 重置预告

本机候选功能，全部使用北京时间（Asia/Shanghai）。新用户默认关闭 `apple_subscription.enabled`、`codex_announcements.enabled` 和 `codex_announcements.analysis_enabled`；需本人选择后才读取系统订阅页或调用模型。原有新闻与金价不依赖这三个开关。

## 两个手动入口

Is 菜单始终提供“立即检查续期日期”和“立即查询重置预告”，不依赖星号。执行中禁止重复发起，结果见运行详情或配置页的本地任务状态。手动请求也遵守正在执行与失败退避约束。

## Apple 日期

通过 Apple 官方订阅入口打开系统 App Store，读取 ChatGPT Plus 行，两次一致后正常退出。只读取日期/状态，不操作续订、取消、购买或登录。

正式 InkSight 应用需要自身的辅助功能权限。测试程序的权限不能替代它。在“系统设置 → 隐私与安全性 → 辅助功能”添加实际安装的 InkSight；权限本身可读取和控制其他应用界面，可在同一页面关闭/移除撤销。无需录屏或全盘访问。权限缺失时不弹系统授权框或反复尝试。

- 距续期日超过三天不自动查询。续期前三天09:00、次日09:00各查询一次，当天不新增查询。
- 启动/唤醒只补一个已到期任务；不补跑历史列表，不唤醒、不解锁。
- 次日仍为旧续期日，从真实查询起至少间隔六小时补查；首次进入补查起最多72小时，重启和重复旧值不能延长期限。仍旧则待确认，改每七天一次。
- 普通失败不覆盖旧记录，至少六小时后再试。授权或认证问题待用户处理。用户已有 App Store/系统设置时直接推迟；用户接管、前台改变、窗口归属不明后不再关闭窗口或退出目标进程。没有强制退出路径。
- 明确取消续费保留“有效至”，停止等待新续期日的密集查询；有效至次日可核对一次。仅有旧日期不能自动判定账户已失效。
- 首次启用没有正式可信基准时，允许一次初始化读取。不会把旧测试结果或硬编码日期冒充新读取。

Apple 的“11月30日续期”仅表示续订日；不等于精确扣款时刻或“有效至”。`month_day` 保留官方原始精度；调度所需年份单独保存依据，不写回官方日期。旧值不会自动顺延一年，跨年/回退等无法确认的日期进入待确认。

支持 typed membership 的固件与真实 PNG 渲染器按同一契约显示会员行。续期显示“套餐 · 续期 MM-DD”，取消续费且来源明确给出到期日时显示“套餐 · 有效至 MM-DD”，来源明确到期时显示“套餐 · 已到期 MM-DD”；未确认显示“套餐 · 待确认”。读取失败保留上次有效日期和日期类型，通过数据状态提示待确认，不把失败变成已到期。会员行保持原右对齐、MiSans 和字体档位，超长套餐缩写以保护与 CODEX 的间距；今日关注没有会员行，不额外添加。

### 发布字段契约

AI 页 `screen.pages.ai.membership` 与 `member.subscription` 为同一 schema=1 对象；统一文档 `ai.member.subscription` 同源。

|字段|含义|
|---|---|
|`date_type`|`renewal`、`valid_until`、`unknown`，不得互换|
|`state`|`renewing`、`valid_until`、`expired`、`unknown`，不凭日期推断到期|
|`date` / `precision`|`MM-DD` / `month_day` 或来源明确年份的 `YYYY-MM-DD` / `date`；未知为 null / unknown|
|`raw_date_text` / `source_wording`|来源原始日期及状态文字；不含调度推断年份|
|`source` / `last_success_at`|`apple_subscription` 与最后成功读取时间|
|`read_status` / `needs_confirmation`|success、failed、blocked、pending 及待确认标记；失败不清空历史读值|

启用 Apple 同步后，该成功来源优先于陈旧手工日期，但不自动改用户套餐。没有可信首次结果时显示待确认，不拿旧手工日期冒充 Apple 结果。未启用同步的用户保持旧数据/固件兼容行为。

续期日期和仅月日的到期日都不写入旧 `valid_until_date`；只有来源明确的完整到期日期才允许该兼容字段存在。更新顺序为先升级支持新字段的固件，再更新 App 发布新数据。旧固件不识别新字段时可能只看到空日期/缺失状态，不能直接把续期日期填进旧字段。回退旧固件前须先协调 App/发布格式，不能将新数据误标为旧有效期。

同值复读仅更新来源元数据，不改变可见版本。日期/采集时间变化不进入 AI 使用活动键；真正的余额/额度变化仍保持原逻辑。原子发布与 GET 回读使用现有链路。

## 每日预告

每日06:00采集一次，错过后在正常使用时补一次。06:00之前启动不会提前抵扣当天槽，但会补昨日已到期任务；停机多日合并近期补抓，不重放过期预告。成功无新信息也算成功。旧余量分档、活跃/临近加频、00:00和辅助源独立轮询均已取消；保留的旧配置字段仅用于兼容读取。

明确暂时失败按15、30、60分钟，之后每三小时重试；重启保留退避。429遵守更严格 Retry-After；401/403不密集重试。辅助源仅在同轮发现原帖链接，不作为官方计划依据；单独失败不推翻成功主源。

原文采集、模型分析和发布状态分别保存。模型失败只重试公开待分析上下文，发布失败由既有发布链路重试，不重复模型调用。没有有效未来事件时显示无预告，过期在本地即时过滤。

## 公开上下文分析

只复用现有 `services.news_deepseek_api_key` 引用链，不要求新增密钥。当前使用 `deepseek-flash`、`thinking.type=disabled`、JSON输出、单次输出最多1000tokens；包括提示的输入按不超过约6000tokens的保守字节上界分批。不会静默切换昂贵模型，不使用付费 Search/Fetch。

只发送公开原文、作者、发布时间、链接与相关公开上下文，不发送账户余额、Apple 页面、凭据或其他私有数据。帖子视为不可信数据，不执行其中指令。全文与字段证据保存在本机；内容/上下文版本hash相同不重复分析。超出预算的上下文等待处理，不静默捏造缺失信息。

模型给出事件类型、未来/部分完成/完成/延期或取消、时间原词、数量/套餐或未知、关联与分阶段计划。程序复核作者、原文引用、时区及时间后才采用，不能因聚合网站的“已落地”标签，把未来时态升级为已到账。`Banked 1/2` 只完成第一阶段，第二阶段仍保留；`Banked 2/2` 结束该计划。预告不等于用户账户已收到重置。

付费调用前先在本地去重并退休原文明确过期、无关、请求/模型宣传和已被新上下文替代的任务，逐项保存状态/原因。仍有效或时间未知的真实计划及其取消/延期回复继续进入证据分析。同一批重叠上下文在输入预算内合并，不为清空旧队列反复调用。重复三次结构/证据异常的相同上下文转为待人工核对，后续原文/上下文有变化才重新入队；网络/限流仍按已授权退避。

实际token计入现有 DeepSeek 用量，费用分别按官方 Flash 人民币/美元单价与实际token计算，并注明这不是单笔扣款回执。内部分析归因沿用现有保护，不把它伪装成用户消费触发切页；不隐藏账户余额或屏蔽真实外部消费。

## 本地状态与兼容性

新增状态文件位于运行版本的 `shared/backend/state/`，沿用原子写入和备份：`apple_subscription.json`、`codex_announcement_analysis.json`，预告原采集状态继续使用 `codex_announcements.json`。这些是私有运行数据，不应提交公共仓库。

更新由版本化运行树迁移现有配置和账本，不覆盖旧版本；回退需要先正常退出本机 App，再恢复备份 App与原版本指针。不得强制结束在途付费任务。本轮本机安装不代表 GitHub 发布、设备烧录或实屏验收。
