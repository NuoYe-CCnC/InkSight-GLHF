# 内容来源与新闻源发布策略收尾任务

日期：2026-09-14

## 目标

在不改变生产配置、现有服务、历史刊物和设备的前提下，为公开源码候选建立保守且可验证的新闻源默认策略，并把代码许可、发行默认、部署者授权和工程验收分成独立门禁。

## 实施范围

1. 逐项核对候选内置新闻源的获取地址、缓存、第三方模型输入、摘要展示、适用主体/条款版本、默认状态和证据缺口。
2. 更正 The Verge 的适用主体为 The Next Media Company 及其 2026-07-08 生效条款；TechCrunch 按其 RSS 条款单列。
3. 对新安装候选采用保守默认：TechCrunch、The Verge 以及无法确认公开 AI 改写范围的内置远程源默认关闭。源代码仍可保留通用 RSS 客户端和用户自行配置入口。
4. 从源获取、缓存候选、提示词构建到自动/手动/补刊统一执行 `source_enabled` 过滤。禁用全部远程源时不下载、不调用模型、不伪报新刊成功，明确回退到本地每日寄语或未配置提示。
5. 迁移只补充缺失的新字段，不覆盖既有用户已经明确保存的来源选项，不改写或删除历史刊物。
6. 对来源开关增加最小必要说明：开关不代表自动获得内容许可；明确受限来源需要独立许可；不要求上传授权文件，不回显密钥。
7. 将项目内容按精确匹配的 MIT 上游、本项目任务记录可追溯修改、第三方改编、未知四类列出。对 `daily_messages.json` 的 12 条文字逐条查找限定范围的生成/修改记录；无法证实的明确标记。
8. 若个别寄语无法追溯，另备全新候选文案供权利人确认；不覆盖生产文件，也不擅自作 CC0 承诺。
9. 添加专项测试，完成全量回归、最终 ZIP 隔离验证、隐私/字体扫描和两次确定性构建。

## 重要边界

- “源码包能按 GPL 分发”不等于“运行时取得第三方新闻内容许可”。
- “新安装默认关闭”只降低默认网络行为风险，不产生授权，也不认定摘要必然侵权。
- 已有 RSS 或官方博客不自动等于允许第三方模型处理、改写和公开再展示。
- 不联系版权方，不接受条款，不注册或购买服务，不调用真实付费 API，不公开上传 GitHub。
- 不重启生产后台，不修改生产数据库/配置，不烧录设备。

## 验收标准

- 禁用源产生 0 次网络请求，旧缓存不能进入新摘要。
- 全部远程源禁用时产生 0 次远程模型调用，并显示真实降级状态。
- 新安装默认安全；现有用户配置迁移不被覆盖。
- 缺少新闻 Key 时保持本地每日寄语路径。
- 来源状态、配置和错误提示一致。
- 全量测试、最终 ZIP 测试、隐私/归档检查与确定性构建通过；未决权属时 `publication_ready=false` 保持不变。
