# 受控固件更新与回退（实验性）

这份说明对应 `v0.1.0-test.4` 源码与管理端流程；上版 `v0.1.0-test.3` Mac App 不包含本流程的回退按钮。只支持 ESP32-S3 N32R16V（32 MB Flash）与 4.26 英寸 800×480 SSD1677 黑白屏。**虽然本版包含按钮和代码，离线模拟、只读设备预检并不等于实机刷写/回退验收。**没有用户单独授权，不应在生产设备上试写。

1. 在本机管理端保存、校验并应用配置。Wi-Fi 列表是完整替换项，检查顺序与密码后再构建。设备端 NVS 可以保留现有设置，但新固件首次启动仍可能按本次构建快照更新 Wi-Fi；不要把“未写 NVS”理解为“运行后绝不改设置”。
2. 在“维护”中检查预检，再构建目标为 `epd_426_ssd1677_s3_n32r16` 的固件。构建产物与配置指纹关联；配置或源码变化后要重新构建。私有密钥和商业字体不进入公开仓库或发布包。
3. 连接唯一目标 USB 设备，选择“已有设备安全更新”，核对设备指纹、32 MB 容量、匹配的分区表与固件摘要。新板的“全新空白开发板”是另一模式，不能用于已有数据的设备。
4. 只有最终勾选确认并点“开始刷写”才会写入。更新先备份 NVS、OTA 启动项、两个应用分区及分区表，逐一记录摘要；然后仅写未运行的应用分区，校验后切换 OTA 启动项。重启前再次读取 NVS，发现变化立即停止自动重启。不会执行全盘擦除，也不会写 LittleFS。
5. 页面分别显示“写入已校验”和“设备联网心跳已确认”。超时不是自动回退，也不能仅凭后端健康接口断言墨水屏已正常显示。请实机观察屏幕、网络和数据。

若需回退，保持原更新产生的私有备份，点击“核对并回退上次更新”。系统会重新识别同一设备，校验原备份、当前分区表、当前 OTA 启动项和**旧应用分区未变化**；预检仅从设备读取。五分钟内再确认后，才仅恢复原 OTA 启动项并校验、重启，**不把旧 NVS 覆盖到设备**。如更新前有近期可信心跳，系统可用旧构建 ID 的新心跳确认回退；否则状态为“已校验，待实体屏确认”，不能声称自动验收完成。

安全拒绝条件包括：设备或分区不符、备份缺失/摘要不符、旧应用被其他更新改动、OTA 启动项已被别的更新改动、确认超时/重放、串口占用。此时不要强行刷写；保存私有备份与日志，先查明设备当前状态。若写入中断导致启动项部分损坏，网页流程不会猜测恢复方式，需按相应私有备份做人工恢复。

较早的刷写任务没有本流程要求的完整双应用分区摘要，不能自动使用新回退按钮。当前实机此前的整片 Flash 备份与恢复记录留在本机私有目录；不要上传到 GitHub。此版网页回退流程仍需一次**单独授权的实机写入与视觉验收**，才能升级其支持声明。
