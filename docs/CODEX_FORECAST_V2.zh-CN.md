# 可信预告 v2（test.18）

此候选只调整公共预告。实际额度、余额、手动重置机会、账户账本、新闻出刊及页面活动判定不由预告推导。默认开关及既有频率不变；没有付费模型、X 凭据、Cookie 或系统弹窗。完整启用需要兼容 v2 的 App 与固件；验收边界见[test.18 说明](releases/v0.1.0-test.18.zh-CN.md)。

## 识别与证据

- FxEmbed 核对指定作者的 handle、稳定用户 ID、帖子 ID、发布时间与本人回复链。两家辅助站只发现原帖；同一 ID 只有一份证据，第三方日期、次数和套餐不成为事件字段。
- 本人链最多 5 条，每一父子都校验身份及发布时间顺序，父子最长相隔 7 天；循环和身份冲突拒绝。跨事件绝不挪用日期、时间或套餐。
- 初始锚点请求限定最近 14 天，最多保留 200 条原帖；仍受每轮 4 个主源 GET、两页及既有页面大小限制。因此历史特别密集时，不能保证首次请求穷尽 14 天。
- 同一作者的 Day 编号系列有明确 Codex＋reset 原文锚点后，可在 14 天内跨编号继承产品背景。只有已观察到连续递增的编号才延长滚动 14 天有效期，单个系列自锚点起硬上限 90 天。明确结束或已识别的其他产品 reset 主题停止继承。记录包含作者、锚点原文/链接、编号、有效期、版本及终止原因；重复抓取不更新锚点时间。
- 套餐未说明可以显示，标记 `plan_scope=unspecified`；不标成所有用户。明确排除当前套餐或限定其他套餐则不显示。限定套餐仍要求新鲜账户证据。
- “Just kidding, today is a reset”按转折后的声明判断；尾部撤回玩笑、请求、条件假设和已完成说明不作为未来计划。更正、延期、取消只更新本事件。规则无法理解的新措辞保留诊断，不调用模型猜测。

## 时间契约

屏幕和菜单显示北京时间。PST 固定 UTC−8，PDT 固定 UTC−7，PT 使用 America/Los_Angeles。相对日期从原帖发布时间计算。支持 in/within/over next 的时长、tomorrow before 10am、今天/明天结束前、tonight、noon 和 by midnight。

同事件父帖的 today 可为午夜回复提供日期；父子跨来源时区日界则降级为时间待定。父子时区冲突且无明确更正时不合成精确时间。午夜截止为该日结束、次日 00:00，不把凌晨 00:00 误作同日开始。

| time_type | target_at | 有效期与显示 |
|---|---|---|
| exact | 有限 Unix 秒 | 截止/精确时间本身失效；`预计 / MM-DD HH:mm 前重置`，at 时不加“前” |
| date_range | null | 真实起止范围结束后失效；整个范围属于一个北京时间日期才显示 `MM-DD，时间待定` |
| unknown | null | 从原始计划起最多 24h；有证据的新更正使用新修订发布时间；显示 `预计重置 / 时间待定` |

有效期不是预计到账时间。重复抓取不续期；缺时区、时间冲突不会编造精确时间。精确事件优先选最近未来一次，否则选择最新可信待定事件。账户额度上涨不是公告兑现证明。

## 协议和终端

`announcements.schema_version=2`，具有 `target_author`、`selected_event`、`canonical_source_url` 和能力声明。事件保留 `event_id`、内容修订摘要 `revision`、时间类型、可空目标、范围、独立 `expires_at`/`valid_until`、原始时间及字段来源。没有以 0 或极大数伪装未知时间。

后端只选择一次，菜单、预览和固件核对同一选中记录，不在客户端另选另一事件。各终端保留 v1 读取能力，v2 缺失/无效时忽略整个可选预告，真实额度继续有效。

已部署 test.17 固件只接受 v1，因此启用 v2 需要同时升级主机 App 和固件。只更新主机时，旧固件会隐藏 v2 预告，其余数据仍按原契约显示。固件联网回执新增 `announcement_schema_max=2`；硬件兼容标识和分区不变。

预告仍位于剩余/7日窗口右侧，基线 y225/y256，右边缘 x461。有效时临时占用可选 API/点数区域；失效恢复原开关。字体、手动次数/到期及底部括号规则不变。

## 原文菜单

Is 有有效计划加一个星号，额度无效但计划有效为 `-*`。菜单“查看预告原文”与有效 v2 选中事件、链接同源；无计划置灰。时间来自回复时打开该回复。

只允许精确的 `https://x.com/<指定作者>/status/<数字ID>` 或 twitter.com 对应路径；不允许用户信息、端口、查询、fragment、其他域或 scheme。菜单打开时重新检查本地有效性；点击再读取本机快照，核对 ID、修订、链接和失效状态。事件已变更则阻止旧点击，不跳到另一个事件，不增加上游轮询。

网络和旧设备快照存在延迟；菜单与屏幕遵循同一选择规则，不承诺不同网络下瞬时同步。

## 辅助重试与诊断

辅助正常间隔至少两小时。暂时网络/连接/读超时及 500/502/503/504，在失败周期起 +10 分钟、+30 分钟各重试一次；成功回常规，两次用尽后等待下一常规周期。周期、计数、预留租约在 I/O 前持久化，跨进程锁避免重启/并发风暴。辅助到期任务独立执行，不为它额外拉主源。

夜间不新增请求时点，只在原有合法主源时刻/补查机会附带处理；白天重试跨夜则顺延，不唤醒 Mac。429 尊重 Retry-After（安全上限 7 天）；401/403/robots 拒绝不快速重试。证书、解码和结构错误不进入 10/30 分钟快速重试；不降低 TLS 校验。

诊断分别记录 DNS、连接、TLS 证书/握手、连接/读超时、HTTP、解码、解析无链接、robots 和未知失败，包含安全错误摘要、阶段及耗时。旧的 network_or_decode 历史无法事后还原，不将当前成功解释为之前封 IP 或超时的证据。

保留 first_seen_at、last_seen_at、first_recognized_at、发布时间、选中及发布快照/回读时间。旧记录缺首次时间时为 unknown/null，不用今天抓取时间补造。管理端展示来源时间、候选原文、可读原因及选择状态。发布快照/云端回读不是设备 ACK；没有实屏证据不得宣称送达。
