# 资讯期刊状态修复：契约、离线验收与升级边界

> 以下为 2026-09-30 第一阶段历史记录，保留当时状态用于溯源。当前发布、部署及待验收事项以 [test.9 说明](releases/v0.1.0-test.9.zh-CN.md)为准，不将历史“尚未部署”理解为现况，也不将旧实机工作当作黄金新版实屏验收。

2026-09-30，第一阶段本地修复记录。尚未部署、发布或写入设备；当前 test.5 生产 App 与设备仍运行原有逻辑。本文不是实机验收通过证明，也不是新的发布授权。

## 根因与证据边界

固件 `panel_pages.cpp` 原先将设备本地 `requested` 和后端 `update_state=due` 两个分支都写成“早报待更新”，主机预览也使用相同硬编码。因此正常中报正文保留、晚报等待更新时，可以显示错误的早报提示。后端原先合并等待与生成状态，仅提供应出期 ID，难以明确显示等待的是哪一期。

用户确认误提示出现于晚报推送之前，正文为正常中报，但没有该画面的精确时间戳。能确认期刊名称错误；不能据此认定 16:55 之前已提前误报。本轮不改变出刊时间、模型调用预算、Token 口径、金价算法或切页策略。

另外补齐跨日首刊前的旧正文提示，以及冷启动没有正文时的空状态；不能让昨日内容被误称为今日正常新闻，或让空期刊退回已退休的三分类资讯源。

## 数据契约

位置：`screen.pages.news_gold.news`。新增字段只扩展 JSON，不改变原有字段类型。日期为北京时间的 `YYYY-MM-DD`；Unix 时间戳用显式 UTC+8 转换，不能随主机时区变化。

```json
{
  "mode": "digest",
  "date": "2026-09-30",
  "schedule_id": "noon",
  "freshness": "fresh",
  "origin": "local-fallback",
  "update_state": "due",
  "expected_schedule_id": "evening",
  "issue_status": {
    "schema": 1,
    "state": "due",
    "as_of_date": "2026-09-30",
    "clock_trusted": true,
    "calendar_trusted": true,
    "coherent": true,
    "current": {
      "date": "2026-09-30", "id": "noon",
      "label": "科技 / AI 中报", "origin": "local-fallback"
    },
    "expected": {
      "date": "2026-09-30", "id": "evening",
      "label": "科技 / AI 晚报", "display_label": "晚报",
      "planned_at": 1790758500, "cutoff_at": 1790776800
    }
  }
}
```

以上是合成契约示例，不是生产数据。正文、当前期身份、应出期状态和正文版本取自同一快照；读取时最多做 3 次乐观一致性重试。不能为读取状态长期持有调度锁，因为生成过程会持锁，导致“生成中”不可见。无法取得稳定快照时，保留通过发布校验的正文，状态降级为 `unknown`，不猜期刊。

- `current` 描述实际可显示正文的日期、期次和来源，不是下一期待发期。
- `expected` 是当前已经到点的最新一期；首刊到点前为 `null`，不指向未来晚报。
- `state`：`published`、`due`、`waiting`、`generating`、`failed`、`expired`、`not-due`、`not-due-empty`、`old`、`unknown`。
- `calendar_trusted=false` 或当日日历行 `workday_degraded=true` 时，不能将周一至五的降级估算冒称法定工作日，应出期名称降级为通用提示。
- 新版保留兼容字段：等待/生成为 `due`；失败/超窗/旧刊为 `not-updated`；不可信为 `unknown`；空正文首刊前为 `due`（通用待更新）；已发布为 `current`。
- 无正文：`mode=status`、`text=""`、`events=[]`、`freshness=missing`、`origin=local-empty`、当前身份为 `null`。不得伪造正文、日期、出刊时刻或标题；正文区域留空，页脚显示状态。
- 快照读取异常：空状态、`freshness=error`、`state=unknown`，不调用旧三分类源、不触发生成或额外采集。
- 合格的 `digest` / `daily_message` 正文已与应出期匹配，即视为出刊成功；完成账本保存稍后到达不能让画面继续显示生成中。备用内容的 `origin` 保持真实来源，不冒称模型生成。
- 休息日历史默认 `morning` 身份维持不变，默认名称为“日报”；用户自定义名称不被覆盖。设备优先采用同版 `expected.display_label`，不从正文标题或 ID 猜名字。

`screen.device_policy.news_check.schedules` 增加经过限制的 `display_label`。标签仅允许 ASCII 字母、数字、空格及 CJK 汉字，最多 12 个字符；精确移除历史配置前缀“科技 / AI ”。设备还须确认实际字号字库有全部字形、名称墨迹宽度不超过 252 px，否则降级为“资讯”。这仅约束更新状态标签，不改变正文内容或已有标题布局。

## 状态决策表

| 条件 | 新固件页脚行为 |
|---|---|
| 同日中报有效，晚报尚未到点 | 保留原聚合数据质量状态；不提示未来晚报待更新 |
| 晚报到点、尚未开始或等待处理 | 晚报待更新 |
| 本期确实处于有效生成记录中 | 晚报生成中 |
| 失败、调用预算耗尽或超过出刊窗口 | 晚报暂未更新；保留实际已有正文 |
| 应出期合格正文成功发布 | 清除期刊覆盖；其他数据陈旧/缺失仍如实报告 |
| 早报失败，中报合格发布 | 中报正常；不保留早报 pending |
| 有效本地备用正文出刊 | 按已发布处理，来源保留 `local-fallback` 等真实值 |
| 次日首刊到点前，保留昨日正文 | 昨日内容 |
| 首刊到点前，正文更早 | 资讯陈旧，不误称昨日 |
| 冷启动无正文、尚未到首刊 | 资讯待更新，正文区留空 |
| 冷启动到点后仍无正文 | 对应期刊待更新；失败/超窗为对应期刊暂未更新 |
| 休息日/自定义名称或逆序时刻 | 按实际配置和日历，选择最新到点期；使用日报/有效自定义名称 |
| 名称非法、过长、缺字或过宽 | 资讯待更新/资讯生成中/资讯暂未更新 |
| 设备时钟未校准 | 时间待校准；不发期刊请求、不猜日期 |
| 日历无当日可信行、缓存数据在未来、字段不同版 | 通用资讯待更新/暂未更新，不猜早中晚 |
| 缓存显示生成中，但超过 600 秒 | 不能继续声称正在生成；降级为待更新或超窗暂未更新 |
| 设备请求失败且绑定当前期、仍在短时有效期 | 对应期刊暂未更新 |
| 本地请求已过期、日期/期次变更或正文已匹配 | 清除本地提示字段；不删除持久请求去重记录 |

固件本地提示绑定 `device_update_issue_key=date|id` 与 `device_update_expires_at`，最长有效范围 900 秒；没有期次绑定的旧提示不能覆盖可信正文。清除的是 JSON 展示字段，不清除 NVS 请求记录，避免重复付费机会。

## 兼容与视觉版本

| 组合 | 结果/限制 |
|---|---|
| 新后端 + 新固件 | 完整期次与细分状态 |
| 旧后端 + 新固件 | 缺少详细契约时使用通用文案；已匹配的可信正文可保留聚合质量状态 |
| 新后端 + 旧固件 | JSON 扩展可兼容解析，但旧固件仍可能硬编码“早报待更新”；不能宣布完整修复 |
| 旧后端 + 旧固件 | 原行为，不保证正确期刊名称 |
| 非稳定快照或未来/跨日期元数据混合 | 降级通用状态，不能拼成虚假的期刊结果 |

正文日期和稳定 `issue_status` 进入 `news_gold_visual_key`，等待→生成→失败→成功等可见变化能触发更新。状态契约不含每轮心跳时间，正文/状态未变化时不会仅因轮询触发额外视觉版本。云端传递必须完整保留同版 `news` 对象。后端不再二次读取另一期正文来取得版本号。

布局保持原有坐标、字体和横线。页脚使用实际 Reg21 字形，给右侧 INKSIGHT 预留 16 px 间隔；超宽文字按字符截断。回归比较确认状态修改不改变 AI 页，也不改变资讯正文区域。

## 已完成离线验收

本地测试不连接生产数据库，不触发模型或强制发刊；所有 Python socket 连接（包括生产 localhost）默认被测试夹具拒绝。状态与数据库均隔离，接口使用合成数据/模拟传输。测试导入不得读取运行 App 的私有状态。

运行命令（路径需指向使用者自己的本地依赖/字体，不应把字体加入公开仓库）：

```sh
PYTHONDONTWRITEBYTECODE=1 \
INKSIGHT_TEST_ARDUINOJSON_INCLUDE=/local/ArduinoJson/src \
INKSIGHT_TEST_FONT_DIR=/local/private/fonts_gen \
python -m pytest shared/backend/tests -q -p no:cacheprovider
```

- 全部项目测试：227 项通过，0 失败、0 跳过，耗时 5.98 秒。新增期刊专项共 66 项，原有 161 项同时复跑；包含主机 C++/Python 行为对照、实际字形/宽度、完整渲染、云端结构传递、后端异常降级、日历降级等。若未提供本地 ArduinoJson/字体路径，相关测试会跳过，不能复述本次零跳过结果。
- 2 个依赖告警：本地 Python 3.9 的 LibreSSL/urllib3 提示、DashScope Assistants 弃用提示。测试禁网，无付费请求；未因此修改生产 App 或升级依赖。

## 下一阶段：需另行批准，不在本轮执行

1. **先备份和比对**：记录当前 App 版本/签名、运行源码版本、唯一发布者及启动项；在权限受限的私有目录备份配置、密钥、数据库、状态、上传文件和运行日志。不要公开备份。设备实读身份、Flash 规格、启动选择、分区表及 NVS/LittleFS/两应用槽备份，并校验哈希；分区或硬件不符就停止，不能擦除迁就新固件。
2. **后端先兼容切换**：停旧发布者后才启用新 App，导入已有私有状态，不重置去重、调用预算、余额/Token 基线或账户资料。先验证旧固件仍能解析扩展字段；它的硬编码错误可能暂存，不能当作失败后无限重发。此阶段完成后才授权设备升级，不并行运行两个发布者。
3. **设备保留设置更新**：使用既有受保护更新流程，实读匹配分区后只写非活动应用槽并校验，再受控更新 OTADATA 选择启动槽；NVS、LittleFS、分区表和 bootloader 不写入。不执行整片擦除、全量 merged 写入或初始化模式。核对已有 Wi-Fi/云盘设置以及页面、缓存和请求去重记录仍保留。
4. **实屏验收**：按用户实际时刻观察中报有效且晚报未到、到点等待、真实生成、成功恢复及午夜首刊前。失败态用已批准的隔离源/安全验证办法，不故意增加付费调用或生产失败；不能为了等待短暂“生成中”反复强制出刊。检查“日报”休息日逻辑、旧提示清理、其他数据陈旧标签、两页稳定切换、Token/金价正常，以及至少一张有时间标识的设备照片。没有实屏或对应日志证据就保持未验收。
5. **回退**：若新固件故障，先核实旧应用槽仍可用，按已有受保护流程恢复备份 OTADATA，不改 NVS/LittleFS；旧应用槽或备份不可信就停手。App 回退时先停新发布者，再恢复旧版本和已校验的兼容私有快照，保持唯一发布者。不能直接覆盖新版本已写入的重要账本，尤其付费请求/预算记录；须先留存并处理其连续性，避免重复生成。
6. 实机通过后，另行获得公开发布许可，更新版本、源码、变更说明和脱敏证据；不得把当前未部署代码或测试镜像标成已在设备验收通过。

## 当前已知限制
