# 发行结论与最小确认项

日期：2026-09-14

## 当前结论

本轮**没有找到可在新发行版中默认启用的每日寄语 API**。已有候选要么只有软件代码许可证、缺少逐条文本/翻译权利证据，要么明确包含第三方现代内容、非商业限制、逐页例外或隐私义务。

因此实际接入状态是：适配契约和模拟测试已实现，所有候选在网络之前由许可门禁拦截，生产调度、配置、现有每日寄语与设备均未改变。API 方案不自动解决旧 `daily_messages.json` 的 CC0 资格，也不解决其他新增代码的 GPL 授权权利。

## 将来启用一个来源所需的最小逐项确认

1. 指定准确提供者、端点、内容集合和条款版本，不接受“所有内容都开源”这类笼统表述。
2. 证明当前部署可复制、缓存并在屏幕展示该文本；需要翻译时另证翻译/改编权。
3. 明确归因文字、原文链接、作者处理、相同方式共享或非商业等义务如何落实。
4. 确认语言、字形、长度、隐私、限流和退出/删除机制满足实际设备场景。
5. 由发布者记录确认人与日期；之后才把该 provider 的两个门禁改为 `true` 并增加网络/缓存集成测试。

在上述确认前，`publication_ready=false` 的内容权利门禁保持不变，不能通过更换 API 名称将未知权利“洗白”。

## 后续状态（阶段 16）

发布者没有启用任何网络寄语 API，而是确认四条本地替换文案并选择按项目 `GPL-3.0-only` 范围处理。旧生产语料不进入候选包，因此本文件记录的阶段 15 阻塞已按替换路径关闭；API 候选仍全部默认禁用。
