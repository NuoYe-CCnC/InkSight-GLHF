# 自动新闻扣费与页面活动归因

日期：2026-09-23

## 现象与根因

设备以 `activity_key` 判断是否出现新的 AI 用量活动。旧实现把 DeepSeek 原始余额直接放入该键，因此计划任务自动生成早报后，供应商余额接口稍后反映扣费时，会被误判成一项独立活动并切到 AI 用量页。

## 修复后的行为

- 屏幕显示仍使用供应商返回的真实余额；当日 Token 仍按实际模型 usage 汇总。
- 自动计划、补跑和自动重试在真实网络发送前写入独立的持久化归因记录，成功返回 usage 后按实际成本结算。
- 与该记录在限定时间、限定金额内匹配的 CNY 余额下降，不再单独改变 `activity_key`。
- 手动发刊不参与抑制；其他 API 使用、充值、USD 变化和 Codex 用量变化仍是正常活动。
- 网络结果不确定时只保留 30 分钟的临时归因；没有结算证据会自动释放，避免无限隐藏活动。
- 已结算调用的匹配窗口为 6 小时，用于覆盖供应商余额延迟；超出窗口后不再抑制。

## 兼容性与验证

固件继续读取原有 `screen.versions.activity_key`，不增加协议字段，因此无需为本修复重新烧录。后端的原始显示数据与活动投影严格分离，旧数据或归因状态不可用时采用保守回退：把余额变化视为普通活动。

自动化覆盖计划任务、重试、延迟余额、进程重启、网络结果不确定、手动发刊、外部用量和充值场景。2026-09-23 全量后端回归为 880 项通过、0 项失败。

## 现场验收边界

本轮未为验证而额外调用付费模型。下一次自然计划发刊后，应确认真实余额与 Token 正常更新，同时设备保持在今日关注页；若期间发生其他独立 AI 活动，页面仍可能按既定规则切换。
